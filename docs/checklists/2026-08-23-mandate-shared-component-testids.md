# Mandate Shared Component Test IDs

- Checklist ID: CHECKLIST-20260823-mandate-shared-component-testids
- Created: 2026-08-23
- Planning completed: 2026-08-23
- Type: Cross-cutting UI contract and pre-commit enforcement
- Source request: Make test IDs mandatory in shared components, document the rule in skill guidance, and add a mandatory mechanical pre-commit check.
- Related checklist: [Shared Web UI Package](./2026-08-22-shared-web-ui-package.md)
- Status legend: `[ ]` incomplete, `[/]` partial, `[x]` complete

## Implementation Description

- Require consumer-provided `data-testid` values on rendered public components exported by `@repo/ui`.
- Preserve non-rendering provider, root, portal, and context helpers as documented exceptions where a test ID cannot identify a DOM node.
- Update existing web and Next consumers with stable test IDs so the stricter shared component types remain buildable.
- Document the shared-component test ID contract in package guidance and portable frontend/component skills.
- Add a staged-file pre-commit checker that rejects shared component changes lacking the required contract.

## Acceptance Criteria

- [x] Every rendered public `@repo/ui` component requires and forwards a non-empty `data-testid`.
- [x] Documented non-rendering helper exceptions are explicit and enforced by the checker.
- [x] Existing `apps/web` and `apps/next` consumers compile with stable test IDs.
- [x] Frontend and shared-component skill guidance requires test IDs for new or changed shared components.
- [x] Future shared components are covered automatically by the checker without requiring a manual checklist update.
- [x] The pre-commit hook rejects invalid staged shared-component changes and accepts valid ones.
- [x] Focused checker tests, UI package checks, affected app checks, and formatting pass.

## Exact Test Cases

### TEST-UI-001: Shared component type requires a test ID

- **Small task:** Require consumer-provided test IDs in rendered shared component props.
- **Source:** User request and `@repo/ui` public component contract.
- **Test place:** TypeScript compile fixture or `@repo/ui` typecheck test.
- **Starting state:** A rendered shared component is used once without `data-testid` and once with `data-testid="save-button"`.
- **Exact input or fixture:** `Button` without the prop; `Button data-testid="save-button"` with the prop.
- **Interaction steps:** Run the UI package typecheck and affected application typechecks.
- **Main behavior:** Missing test IDs are rejected while supplied test IDs are accepted.
- **Expected result:** The missing prop produces a type error in the negative fixture; the supplied prop compiles.
- **Must change:** Public rendered component prop types and existing consumers.
- **Must not happen:** Test IDs must not be optional or silently generated by the library.
- **Planned command:** `pnpm --filter @repo/ui typecheck && pnpm --filter web typecheck && pnpm --filter next typecheck`
- **Expected result before the code change:** Existing components do not require test IDs; the negative contract check is absent.
- **First observed run:** Initial workspace typecheck failed in `apps/next` because existing consumers omitted the required prop.
- **Passing rerun:** `pnpm typecheck` passed all 20 tasks on 2026-08-23.

## Risks And Non-Goals

- This does not require hardcoded test ID values; consumers provide instance-specific values.
- Non-rendering context and portal helpers remain exceptions because they do not identify a DOM target.
- Native and Expo component libraries are outside the `@repo/ui` web shared-component contract.
- The checker must remain path-based and generic so future shared components inherit the rule automatically.
- Existing application test IDs must be stable and descriptive without exposing private data.
